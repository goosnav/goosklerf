# Changelog

One line per sprint. Cites which requirements it touches.

## 2026-05-06

- **Sprint 0** — archive old code; scaffold new pnpm monorepo (`packages/cards,engine,ai`, `apps/play-cli`). No requirements covered.
- **Sprint 0.5** — formal documentation foundation: `SPEC-rules.md` (186 reqs), `SPEC-system.md`, `TUTORIAL.md`, `AGENTS.md`. No requirements *covered* by code yet — but every requirement now has an ID for tests to cite.
- **Sprint 1** — `@gk/cards` package: schema, validator, CSV importer, JSON loader. Covers **R2.1** (card type enumeration), **R2.2** (entity required fields), **R2.3** (fortress required fields), **R2.4** (item capacity / no required stats). 26 tests; build emits 127 cards from `card_data-003.csv` (56 fully_implemented, 60 not_implemented, 11 data_error). Zod schema validates the JSON load boundary.
- **Sprint 1.5 (housekeeping)** — Folder layout corrected by user: `videogame/gk_videogame_v2/` is the active code, `videogame/archive/gk_videogame_v1/` archives the old codebase + the canonical CSV. Build paths and test paths updated. Rule spec regenerated (`SPEC-rules.md` v2): scoped to Classic Goosklerf only, dropped Chessklerf / Campaign / Goosklerf I backcompat / Basic-vs-Advanced distinction; 67 testable requirements across 10 Parts. All citations across `packages/cards/` source, tests, `SPEC-system.md`, `TUTORIAL.md`, `AGENTS.md` realigned to the new R-IDs. 26/26 tests still green.
- **Sprint 2** — `@gk/engine` foundation: `SeededRng` (port of v1, plus `rollNd6`, `pick`, `pickWeighted`, `rngFromState`); state types (`GameState`, `Player`, `CardInstance`, `Fortress`, `Engagement`, `DamageEvent`, `Phase`, `LandlordStatus`, `Outcome`, `LogEntry`, `ZoneRef`, `DeckSize`, identifiers); `Result<T, E>`; pure helpers (`playerById`, `cardById`, `getZoneContents`, `findFortress`, `totalFortressesOnBoard`, `cloneState`, `zoneSize`). 41 new tests across `tests/engine/{rng,state}.test.ts`. Total: **67 tests**. Typecheck clean. **Reqs touched (type-level only):** R1.4, R2.1–R2.7, R3.1–R3.5, R3.6, R3.8, R3.10, R4.1, R6.x (engagement shape), R7.2, R10.3, R10.7. No game logic shipped yet — that starts Sprint 3.
- **Sprint 3** — `@gk/engine/setup.ts`: `setupGame({ seed, players, deckSize, cardDatabase, enableShop? })` returns `Result<GameState>`. Builds regime-legal decks per player, draws shop (R1.5: 3/7/7), draws 7-card hand with auto-mulligan (R1.3), randomly chooses first player (R1.4), constructs initial GameState in `card_play` phase. **Reqs covered:** **R1.2** (deck regimes + 3-copy + minimums), **R1.3** (hand + mulligan), **R1.4** (turn order), **R1.5** (shop). 29 new tests; total: **96 tests**. **Type-contract refactor:** shop moved from `GameState.shop` (shared) → `Player.shop` (per-player), per R1.5/R5.6. ZoneRef.shop now requires ownerId. **Scope adjustment:** deck pool broadened to admit `not_implemented` cards (text ignored at M1) because zero fortresses are tagged fully_implemented in the canonical CSV. See `docs/decisions/0001-card-pool-includes-not-implemented-at-m1.md`. Also relaxed tsconfig `exactOptionalPropertyTypes` (clashes with Zod's optional inference).
- **Sprint 4** — CLI shell + render layer. `apps/play-cli/src/{args,glyphs,render,commands,inspect,main}.ts`: hand-rolled flag parser (--seed, --players, --deck-size, --no-shop, --script, --no-color, --help), Unicode glyph table (🛡 ⚔ 🎒 🧪, dice faces ⚀..⚅, 🌀 for text-silenced cards), pure render functions (header / battlefield / suburbs / hand / shop / log / prompt), and a card inspector. `pnpm play` now runs `setupGame()` and renders the initial state with color (TTY-aware) and a readline prompt (`q` quits, `r` re-renders, `?` prints help, `i` inspects cards). 22 new tests including a stable render snapshot; total: **118 tests**. Added `picocolors ^1.1.1` dep. **First user-visible milestone**: the launcher (`Play-Goosklerf.command` etc.) now displays a real game board.
- **Launcher scripts** — `Play-Goosklerf.{command,bat,ps1}` and `play-goosklerf.sh` at the `videogame/` root. Click-to-run for macOS / Linux / Windows-cmd / Windows-PowerShell. Each launcher checks for pnpm, runs `pnpm install` and `pnpm cards:build` on first launch, then `pnpm play`. `videogame/HOW-TO-RUN.md` documents the user-facing workflow.
- **Sprint 5** — Engine Card Play phase. Added `Action` / `PlacementRef`, top-level `reduce(state, action, { cardDatabase })`, Card Play handlers, and reducer log helper. Covers **R5.1** (3-card play/discard quota), **R5.2** (type-specific placement), **R5.3** (battlefield/fortress/item capacity), and **R5.4** (consumables equip during Card Play and do not resolve yet). CLI now supports `p N bf`, `p N f M`, `p N s`, `p N e M`, `d N`, and `e`. 18 new tests; total: **136 tests**.
- **Sprint 5.5** — Make the game actually loopable. Three pieces:
  - **Phase rotation** (`packages/engine/src/rules/phase.ts`): `END_PHASE` now handles all 5 phases. Combat / Movement / Card Draw are no-op stubs that auto-advance (their real logic lands Sprints 6+, 8, 9). End of Victory Check rotates active player, increments turn counter, and resets `cardPlay` state for the incoming player. **Reqs touched:** R4.1 (turn structure). 9 new engine tests in `phase.test.ts`.
  - **Stub AI Card Play** (`apps/play-cli/src/autoplay.ts`): `runAutoplay()` walks the active player through their turn whenever they're an AI, then auto-advances stub phases until human input is required again. Deterministic "first legal play" strategy now; Sprint 11 swaps in personality-weighted picks. Safety cap of 200 dispatch steps per call to guard against infinite loops.
  - **UX**: `p N` (no target) auto-picks the only legal placement; if multiple legal placements exist, the error lists them as copy-pasteable hints. `commandPaletteLine()` and `commandHelpText()` updated. 3 new commands tests; total: **148 tests**.
  - End-to-end: human + 1 AI through 2 turns now smoke-tests cleanly. AI plays its full Card Play, all stub phases advance, control returns to the human in turn 2.
- **Sprint 6** — Engine Combat basics. Added battlefield `DECLARE_ENGAGEMENT`, `NORMAL_ATTACK`, `PASS_ACTION`, deterministic dice through saved `rngState`, Initial Volley, one-action-per-entity round flow, automatic side/round advance, engagement cleanup, damage application, and entity defeat with equipped items following to graveyard. Combat staging now allows owned fortress occupants to sortie into battlefield engagements and lose fortress positioning buffs immediately. Fortress Attack buffs apply to occupants' Initial Volley / combat rolls per R3.10. CLI renders an engagement panel and supports `decl A pN`, side-labeled attacks (`att aN dM` / `att dN aM`), and side-labeled pass commands; autoplay has deterministic baseline AI combat. **Reqs covered:** R6.1, R6.2, R6.3, R6.4, R6.5, R6.6, R6.7, R7.1, R7.3, R3.10. 28 new tests; total: **176 tests**.
- **Sprint 6.5** — Stat-buff fidelity preflight for fortress assault. Added `@gk/engine` runtime stat helpers (`entityStats`, `modifiedEntityAttack`, `modifiedEntityMaxHp`) so Card Play, Combat, inspection, and rendering all use the same item/fortress buff math. HP buffs now raise current HP when equipped or entered, clamp current HP when a fortress HP buff is lost during staging, and show as real combat durability. CLI board/engagement rows now render modified Attack deltas and current/max HP when buffs are active; `i ...` inspection reports current vs printed Attack and max HP. **Reqs tightened:** R2.4, R2.6, R3.10, R6.2, R6.5, R7.1. 4 new tests; total: **180 tests**.
- **Sprint 7** — Fortress assault, capture, and destruction. `EngagementSpec` now supports `fortress_assault`; attackers can declare assaults against one or more enemy fortresses, attack defenders inside or target the fortress directly, destroy fortresses at 0 HP with occupants/items sent to original-owner graveyards, and resolve cleared fortresses with `capture`, `destroy`, or `leave`. Capture moves the fortress slot to the attacker's suburbs, preserves original card ownership, and requires at least one surviving attacker to garrison. CLI adds `assault A pN fM[,fK]`, `att aN fM`, `cap fN aM[,aK]`, `burn fN`, and `leave fN`; render adds `[fN]` target labels; AI can baseline assault/capture when no battlefield target exists. **Reqs covered:** R6.8, R6.9, R6.10, R6.11, R7.4. 8 new tests; total: **188 tests**.
- **Sprint 8** — Movement phase. Added `MOVE_ENTITY` and `MovementDestinationRef`, plus `packages/engine/src/rules/movement.ts`. The active player can move owned entities from battlefield to a controlled fortress, from a controlled fortress to battlefield, or between controlled fortresses; battlefield/fortress capacity is enforced; equipped items stay attached; entering/leaving HP-buff fortresses updates current and modified max HP immediately. CLI adds `mv bN fM`, `mv fM.N bf`, and `mv fM.N fK`; the prompt/help text documents those forms; human Movement now waits for input while baseline AI skips Movement with `END_PHASE`. **Reqs covered:** R8.1, R8.2, R2.7, R3.8, R3.10. 10 new tests; total: **198 tests**.
- **Sprint 9 is next**: Card Draw phase.
